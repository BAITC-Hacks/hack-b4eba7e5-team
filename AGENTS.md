# Правила разработки команды

Этот файл — правила проекта для людей и ИИ-ассистентов (Claude Code, Codex, Cursor, ChatGPT).
Лежит в корне репозитория как `AGENTS.md`: Codex и Cursor читают его сами, Claude Code — через `CLAUDE.md`.
Если твой инструмент его не видит — вставь текст целиком в правила проекта или в начало чата.

## 0. Главное для ИИ-ассистента

- Задача проекта — кейс «Аким на 5 часов»: ТЗ, правила и формула Score в `docs/TZ.md`, исходные данные в
  `docs/dataset.json`. Данные и формулу не менять: все команды стартуют с одинаковых значений.
- Проект **уже существует** в репозитории команды. **Не создавай новый проект и не генерируй каркас**:
  никаких `create-vite`, `create-next-app`, `npm init`, `uv init`, новых `package.json`/`pyproject.toml`.
  Если кода у тебя перед глазами нет — попроси человека склонировать репо, а не пиши своё.
- Перед правкой прочитай этот файл и файлы, которые меняешь. Повторяй устройство соседнего кода —
  образцы: `backend/app/routes/chat.py` (роутер), `frontend/src/pages/ChatPage.tsx` (экран).
- Стек зафиксирован (раздел 2). Новые фреймворки, библиотеки, базы данных, Docker — только после согласования с командой.
- Делай маленькие изменения под конкретную задачу. Не переписывай и не «улучшай» чужой код заодно.
- Если задача требует отступить от этих правил — остановись и спроси человека.

## 1. Репозиторий и git

- Репо: https://github.com/BAITC-Hacks/hack-b4eba7e5-team, основная ветка `main`. С неё выкатывается демо, она всегда рабочая.
- Свою задачу делай в ветке `<имя>/<фича>` (например `aidos/upload`). В `main` — через Pull Request после зелёных проверок (раздел 7);
  ревью не обязательно, проверки обязательны. Перед PR: `git pull --rebase origin main`.
- Коммиты маленькие, сообщение на русском и по сути: «Загрузка PDF и извлечение текста». Без трейлеров `Co-Authored-By`.
- Не используй `git add -A` / `git add .`: добавляй файлы поимённо, перед коммитом смотри `git status`.
- Никогда не коммить: `.env`, ключи, `node_modules/`, `.venv/`, `dist/`, базы и дампы, большие файлы.
- Зависимости меняются только вместе с lock-файлом: `backend/uv.lock`, `frontend/pnpm-lock.yaml`.

## 2. Стек (не менять)

| Часть | Технологии | Менеджер пакетов |
|---|---|---|
| backend | Python 3.13, FastAPI, pydantic v2, OpenAI SDK | `uv` |
| frontend | Vite, React 19, TypeScript, Tailwind CSS v4 | `pnpm` |
| ИИ | OpenAI API (или любой OpenAI-совместимый провайдер — через env) | — |
| прод | nginx + uvicorn под systemd на нашем сервере | — |

Без согласования нельзя: Next.js и другие фронт-фреймворки, Docker, Postgres/Mongo/Redis, LangChain/LlamaIndex,
UI-киты (MUI, Ant, shadcn), `npm`/`yarn`/`pip`/`poetry` вместо `pnpm`/`uv`.
Хранить данные нужно — SQLite в каталоге `DATA_DIR` (настройка `data_dir` в `config.py`).

## 3. Структура

```
backend/
  app/main.py          приложение: request_id, логи, обработка ошибок, /health, подключение роутеров
  app/routes/<фича>.py эндпоинты — по файлу на фичу (образец: routes/chat.py)
  app/llm.py           ЕДИНСТВЕННОЕ место вызова модели
  app/sse.py           отдача стрима (SSE) — один формат на все стримы
  app/config.py        все настройки из env
  app/logs.py          JSON-логи: log_event()
  app/llm_check.py     проверка ключа и доступных моделей
  tests/               pytest, работают без сети
frontend/
  src/App.tsx          каркас страницы
  src/pages/           экраны (образец: pages/ChatPage.tsx)
  src/components/      переиспользуемые компоненты
  src/lib/api.ts       ЕДИНСТВЕННОЕ место запросов к бэкенду
deploy/                выкатка на сервер — не трогать (раздел 9)
dev.sh                 локальный запуск бэка и фронта
```

## 4. Бэкенд

- Новый эндпоинт — файл `backend/app/routes/<фича>.py` с `router = APIRouter(prefix="/api/<фича>", tags=["<фича>"])`,
  подключается одной строкой в `main.py`: `app.include_router(<фича>.router)`.
- Все пути API начинаются с `/api/` — nginx отдаёт бэкенду только их.
- Тело запроса и ответ — pydantic-модели с ограничениями (`Field(max_length=..., min_length=...)`), не голые `dict`.
- Ошибка для пользователя — `HTTPException(status_code, detail="понятный текст по-русски")`.
  Трейсбэки, ключи и внутренние адреса наружу не отдаём: необработанное исключение middleware сам превратит в 500 с `request_id`.
- Внутри `async def` — только асинхронный ввод-вывод: `httpx.AsyncClient` с таймаутом.
  Нельзя `requests`, `time.sleep`, долгие синхронные вычисления (их — в `await asyncio.to_thread(...)`).
- Новая настройка — поле в `app/config.py` + строка в `backend/.env.example`. `os.environ` напрямую не читать.
- Логи — `log_event(log, "имя_события", поле=значение)` из `app/logs.py`, не `print`.
  В логи не писать ключи, персональные данные и полные тексты пользователей.
- Файлы (загрузки, SQLite) — только внутри `get_settings().data_dir`.

## 5. ИИ (OpenAI)

- Модель вызывается **только** через `backend/app/llm.py`. `import openai` в других файлах запрещён.
  - `await llm.complete(messages)` — ответ текстом;
  - `await llm.complete_json(messages, Schema)` — ответ сразу объектом pydantic-схемы (structured output). JSON руками не парсим;
  - `llm.stream(messages)` — поток текста; отдаётся одной строкой `return sse.stream_text(llm.stream(messages))`,
    во фронте читается `streamSSE()`.
- В обёртке уже есть лимит времени, повторы, запасная модель, понятные ошибки (`LLMError`), кеш и mock-режим.
  Не дублируй это в роутах и не глуши `LLMError` — его превращает в ответ общий обработчик.
- Ответ, который может идти дольше ~10 секунд, — только стримом: пустой экран на демо хуже всего.
- Системные промпты — константой `SYSTEM_PROMPT` в модуле фичи (или `app/prompts/<фича>.py`), не строкой посреди функции.
- Модель, ключ и провайдер — только через env: `OPENAI_MODEL`, `OPENAI_FALLBACK_MODEL`, `OPENAI_API_KEY`, `OPENAI_BASE_URL`.
  Названия моделей в коде не хардкодить; нужна отдельная модель под фичу — новая настройка в `config.py`.
- Каждая фича обязана работать без ключа, в mock-режиме: на нём идут тесты, и так демо переживёт падение API.
- `LLM_CACHE=true` включает кеш ответов — одинаковый запрос отвечается мгновенно и одинаково (включаем перед показом).

## 6. Фронтенд

- Запросы — только через `src/lib/api.ts`: `api<T>(path, { method, json })` и `streamSSE(path, body, onDelta)`.
  Пути относительные (`/api/...`), никаких `http://localhost:8000`.
- Стили — только классы Tailwind. Без отдельных CSS-файлов и inline-стилей.
- У каждого экрана есть состояния «загрузка», «пусто», «ошибка». Ошибку показываем текстом `ApiError.message`, рядом `#request_id`.
- Тексты интерфейса по-русски, без выдуманных цифр и данных.
- Вёрстка работает на ширине телефона (от 360px).
- Компоненты функциональные, типизированные, без `any`. Новые npm-пакеты — по согласованию.

## 7. Проверки перед пушем

```bash
cd backend && uv run pytest -q && uv run ruff check app tests && uv run ruff format --check app tests
cd frontend && pnpm lint && pnpm build
```

- На новый эндпоинт — минимум один тест в `backend/tests/` (без сети, в mock-режиме; образец — `tests/test_smoke.py`).
  Логику вокруг модели проверяют с фейковым клиентом — образец `tests/test_llm.py`.
- Свой сценарий пройти руками в браузере через `./dev.sh`.

## 8. Локальный запуск

- Нужны `uv`, `pnpm`, Node 20+.
- `cp backend/.env.example backend/.env` и вписать свой `OPENAI_API_KEY`. Без ключа бэкенд отвечает заглушкой — для вёрстки хватает.
- `./dev.sh` → http://127.0.0.1:5173 (бэкенд на :8000, `/api` проксируется). Swagger: http://127.0.0.1:8000/api/docs.
- Проверить ключ и посмотреть доступные модели: `cd backend && uv run python -m app.llm_check`.

## 9. Деплой и сервер

- Демо: https://hackalem.oqcrm.kz
- Выкатывает только Орынтай: `deploy/deploy.sh` (тесты → сборка → релиз → health-check → автооткат при провале),
  откат `deploy/rollback.sh`, логи `deploy/logs.sh`, секреты `deploy/set-secret.sh`, проверка ключа `deploy/llm-check.sh`.
  Остальные: влили в `main` → написали в чат команды.
- `deploy/` и настройки сервера без Орынтая не менять. Сервер общий с чужим продом.
- Секреты — только в `backend/.env` локально и в `/etc/hackalem/app.env` на сервере.
  Никогда в репо, в код, на скриншоты и в чаты, в том числе с ИИ.

## 10. Стиль кода

- Комментарии — коротко, по-русски: что делает код и зачем. Без дат, сроков и истории разработки.
- Имена по-английски и по смыслу: Python — `snake_case`, TypeScript — `camelCase`, компоненты — `PascalCase`.
- Python форматирует `ruff format`, длина строки 110.
