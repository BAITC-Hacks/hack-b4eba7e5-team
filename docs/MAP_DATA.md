# Данные карты Астаны

`frontend/src/data/districts.json` — производная от `districts.geojson` из переданного
архива `astana_map_export.zip`. По README и manifest архива источник границ —
OpenStreetMap / Nominatim, снимок остальных геослоёв — Geofabrik Kazakhstan от
22.09.2026. Координаты WGS84 / EPSG:4326, порядок `[долгота, широта]`.

Контрольные суммы SHA-256 исходников:

- Архив: `71911504972a8292a9ba472be5333a8ca46177c75e967ace14ee7e1d89364218`.
- `districts.geojson`: `c103ec8413b9500a63c61b314472413a30613f7827ad4f20e98f933502e3cf5d`.

## Связь с кейсом

| Название в архиве | `id` приложения | Название в интерфейсе | В расчёте |
|---|---|---|---|
| Есіл | `yesil` | Есиль | да |
| Алматы | `almaty` | Алматы | да |
| Сарыарқа | `saryarka` | Сарыарка | да |
| Байқоңыр | `baikonur` | Байконур | да |
| Нұра | `nura` | Нура | да |
| Сарайшық | `sarayshyk` | Сарайшық | нет |

Пять расчётных районов и их названия взяты из `docs/dataset.json`. Данные кейса и
формула Score не изменены. Сарайшық остаётся справочным контуром с
`case_district: false`: ему нельзя присваивать баллы или решения другого района.
`feature.id` и `properties.id` одинаковы и стабильны. `label_point` расположен внутри
самой большой части района; `bounds` охватывает все его части.

## Исправление пересечений

В архиве шесть уникальных features без повторяющихся имён и OSM ID. Алматы имеет две
части MultiPolygon, Байқоңыр — три, Есіл — две. Это отдельные территории, которые
не следует считать дублями или удалять. Остальные районы — Polygon.

Исходная граница Есіл содержит всю Нұра. Поэтому даже один фильтр выбранного района
в демо архива визуально окрашивает сразу две территории. Кроме того, на стыке
границ обнаружены маленькие пересечения Есіл с Байқоңыр и Сарыарқа.

При импорте изменена только геометрия Есиля по правилу:

```python
yesil = original_yesil.difference(unary_union([nura, baikonur, saryarka]))
```

Это разность исходных контуров, а не новая нарисованная граница. Остальные пять
геометрий сохранены без изменений. Исходные координаты не округлялись; дополнительные
вершины вычислены только в местах пересечения исходных рёбер. Отдельная южная часть
Есиля сохранена. Результат — нормализация переданного снимка для приложения, а не
подтверждение актуальности официальных административных границ.

Однократная проверка выполнена Shapely 2.1.2 вне зависимостей приложения:

- Все исходные и итоговые геометрии валидны.
- Исходные пересечения: Есіл–Нұра ≈188.32 км², Есіл–Байқоңыр ≈54.24 м²,
  Есіл–Сарыарқа ≈24.47 м². Площади приблизительные, рассчитаны из WGS84 при широте 51.1°.
- Площадь пересечения каждой пары после преобразования равна `0`.
- `unary_union(original).symmetric_difference(unary_union(normalized)).area == 0.0`:
  общее покрытие сохранено без добавленных участков и пробелов.
- Площадь объединения в координатах исходника: `0.10276142071370954` квадратных градусов.
- Сохранены 10 отдельных полигонов, геометрия Есиля остаётся MultiPolygon из двух частей.

`backend/tests/test_map_data.py` работает без Shapely и сети: проверяет IDs кейса,
внутренние точки всех трёх бывших пересечений, отдельные территории, замкнутость
колец, расположение подписей, bounds и суммарную площадь. Он защищает от повторного
импорта перекрывающейся границы Есиля и потери отдельных частей.

## Использование в интерфейсе

Карта и панель района должны получать один `selectedDistrictId` из состояния
страницы. Выбранные заливка, обводка, подпись и кнопка проверяют равенство этому ID.
Hover не должен выглядеть как второе выделение. Клик по Сарайшық не меняет расчётный
район. При наведении и анимации нельзя менять принадлежность геометрий районам.

Тематические OSM-слои показывают расположение нанесённых объектов. Это не показатели
качества, полноты услуг или реальные измерения баллов 0–100. В исходной выгрузке
отношения OSM не включены, полнота объектов не гарантирована, привязка к району
сделана по точке либо средней вершине линии. Поле `district` из архива нельзя
использовать для вычисления значений модели, особенно после исправления пересечений.

Файлы `frontend/public/map/*.json` — производные от тематических GeoJSON архива.
В свойствах оставлены только название и OSM ID/type; тематические данные служат
фоном, без статистической связи с баллами кейса. В `green_spaces.json` сохранены все
6942 объекта: 6940 полигонов и две точки. Чтобы уменьшить загрузку, геометрии этого
слоя упрощены Shapely с `preserve_topology=True`, `tolerance=0.00002` градуса и
округлением координат до шести знаков. Для 27 объектов упрощение отменено из-за
отклонения границы, ещё для трёх отменено округление. Все итоговые геометрии валидны,
число полигонов и отверстий каждого объекта сохранено. Проверенное максимальное
расстояние Хаусдорфа до исходника — `0.000020683` градуса (не более примерно 2.3 м).
Размер слоя уменьшен с 2 550 210 до 1 908 520 байт (25.2%). Суммарная площадь
изменилась на −0.0249%, сумма симметрических разностей — 0.162% исходной площади.
Это упрощение только справочного слоя зелени: границы районов не упрощались.
