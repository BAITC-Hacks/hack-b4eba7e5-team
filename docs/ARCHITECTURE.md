# Архитектура «Аким на 5 часов»

Документ описывает реализованное приложение. Задача, данные и формула — [TZ.md](TZ.md).

## Расчёт и данные

`backend/app/sim.py` загружает неизменяемый датасет из `app/data/dataset.json`.
Тест сверяет его с официальным `docs/dataset.json`. Сервер проверяет все правила, неизвестные ID,
бюджет, районы, несовместимости и количество решений. Невалидный план не получает Score.

Эффекты умножаются на `(8 − lag) / 8`, синергии добавляются целиком, затем показатели ограничиваются
диапазоном 0–100. Районные индексы учитывают веса показателей, средний индекс — доли населения.
`Score = 0.7 × D_avg + 0.3 × min(D) − N_crit`, критические значения строго ниже 40.
В расчётах нет округления. База: **52.55768**, пример ТЗ: **56.54307**, стоимость примера: **95**.

`contributions()` рассчитывает точные вклады Шепли по 32 поднаборам выбранных мер. Их сумма равна
приросту Score относительно базы. Это распределение общего эффекта, включая синергии, штрафы и минимум;
оно отличается от прямого изменения показателя отдельной мерой. Поднаборы служат только внутреннему
расчёту вкладов: пользовательский план по-прежнему должен содержать ровно пять решений.

## Поиск и сравнение

`backend/app/optimizer.py` перебирает наборы мер и все назначения районов, отсекая нарушения правил.
Результаты локальных поднаборов заранее рассчитываются для каждого района: это ускоряет поиск
без NumPy и изменения формулы. Лучший план пересчитывается и валидируется основным движком.

В официальных данных **694 395** допустимых сценариев. Точный максимум: **57.236735**, стоимость **98**:
M2 и M14 на город; M3, M8 и M9 в Нуре. При одинаковом Score предпочтение получает меньшая стоимость.
Признак `exact` выдаётся только после полного перебора. Результат кешируется в памяти процесса;
блокировка объединяет одновременные поиски. Вычисления запускаются через `asyncio.to_thread` по запросу.

Советник сравнивает предложение с рассчитанным планом или исходной базой, если плана ещё нет.
Показывает Score, стоимость, критические показатели, состав и замены. Применение происходит только
кнопкой пользователя, после чего новый план вновь отправляется в `/evaluate`.

## Аналитик

`backend/app/analysis.py` строит серверные факты: исходные/итоговые значения, дельты районов и показателей,
вклады Шепли, а для советника — проверенное предложение и сравнение с текущим планом.

В живом режиме `llm.complete_json()` возвращает разделы анализа и ссылки `fact_ids`. Для каждого раздела
есть разрешённые факты: например, сильные стороны ссылаются на положительные вклады, риски — на критические
показатели или отрицательные вклады. Модель выбирает аргументы и их порядок; пользователь видит текст
самих серверных фактов. Свободный текст и числа от модели не отображаются. Так исключены придуманные
числа, противоречащие расчёту утверждения и сырые маркеры Markdown.

Неверная схема или ссылка: одна повторная попытка, затем явно помеченный шаблонный анализ.
Без ключа или при `LLM_MOCK=true` работает шаблон по тем же фактам. Ошибка провайдера остаётся видимой
через SSE `error`; уже рассчитанное предложение сохраняется и может быть применено.
Все обращения к модели идут только через `app/llm.py`, с существующими настройками, кешем и fallback.

## API и защита

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/sim/config` | Датасет, предпросмотр эффектов, база, пример и режим аналитика |
| POST | `/api/sim/evaluate` | Валидность, нарушения, рассчитанный результат или `null` |
| POST | `/api/sim/analyze` | SSE-анализ допустимого плана |
| POST | `/api/sim/optimize` | SSE: статус поиска, оптимум, сравнение и рекомендации |

POST принимает `{decisions: [{measure_id, district_id}]}`. Для `/optimize` пустой список означает
сравнение с базой; непустой список должен быть полным допустимым планом.

`/api/chat` и `/api/chat/stream` подключаются только при `APP_ENV=dev` как учебные примеры.
В проде этих маршрутов нет. Анализ и советник делят `AI_REQUESTS_PER_MINUTE` (по умолчанию 10):
лимит на процесс и скользящее окно 60 секунд. Он проверяется после валидации плана, до дорогой работы.
Ответ при превышении — 429 с `Retry-After` и request ID. Подмена `X-Forwarded-For` лимит не обходит.
При нескольких процессах лимит умножается на их число; для распределённого лимита потребуется отдельное
решение. Обычные расчёты не расходуют этот лимит.

## Потоки и фронтенд

`app/sse.py` поддерживает `status`, `delta`, `result`, `ping`, `done`, `error`; heartbeat раз в 10 секунд.
Успешный поток обязательно заканчивается `done: true`, ошибочный — `error` без `done`.
У модели отсутствие нормального завершения, обрезка по длине и таймаут считаются ошибкой,
а незавершённый ответ не попадает в кеш.

`frontend/src/lib/api.ts` — единственная точка запросов. `streamSSE` проверяет типы событий, поддерживает
разбиение UTF-8/события по чанкам и CRLF. EOF без `done`, повреждённое событие и сетевой обрыв вызывают
`ApiError`. Reader отменяется и освобождается. Отмена пользователем отличается от сетевой ошибки.

`SimulatorPage.tsx` помечает незавершённое объяснение после ошибки/остановки.
`PlanAdvisor.tsx` показывает статус, сравнение, предложение и кнопку применения.
При изменении плана запросы отменяются, устаревшее предложение очищается.
Оба TypeScript-конфига используют `strict`. Стили остаются на Tailwind, новые зависимости не добавлены.

## Проверки и границы

Backend: `uv run pytest -q`, `uv run ruff check app tests`, `uv run ruff format --check app tests`.
Frontend: `node --test tests/*.test.mjs`, `pnpm lint`, `pnpm build`.
Тесты без сети проверяют исходные числа, правила и синергии, вклады Шепли, точный оптимум и его сверку
с независимым перебором на уменьшенных каталогах, факты, SSE, лимит запросов и недоступность чата в проде.
Ручной сценарий: поиск → сравнение → применение → повторный расчёт → объяснение, включая ширину 360 px.

Агент с function calling и произвольной целью, ограничения на поиск, сохранение сценариев,
лидерборд, события и генерация презентации не реализованы. Точный максимум относится только к модели ТЗ.
Деплой выполняется существующими скриптами после PR и зелёных проверок; настройки сервера не меняются.
