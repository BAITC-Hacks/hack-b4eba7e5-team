# Продуктовые модули после первого MVP

Задачи распределяются между фуллстеками: один человек доводит свою функцию целиком, включая интерфейс,
API при необходимости и проверку сценария. Готовая основа — каталог, правила, расчёт и аналитик.
Ниже независимые продолжения; это задачи, а не обещание уже работающих функций.

## 1. Исследование города на карте

Пользователь выбирает район на карте, видит его проблемы и назначает туда мероприятие.

- Заменить центральные карточки районов картой Астаны, сохранив общий выбор района.
- Отделить географию от неизменного учебного датасета: на карте показать пять районов кейса.
  Не выдавать схематичные границы или местоположение мер за точные данные организаторов.
- Легенда, подсветка выбранного района, показатели до/после, мобильный вариант.
- При недоступности тайлов сохранить возможность выбрать район и завершить расчёт.
- MapLibre и источник тайлов согласовать перед добавлением зависимости; сохранить атрибуцию.
  3D-здания — дополнительный эффект после рабочего выбора района.

Готово, когда выбор района связан с каталогом и результатом, а отказ карты не ломает симуляцию.
Граница модуля: компонент карты получает районы, выбранный район, результат и callback выбора.

## 2. Сравнение двух решений

Пользователь сохраняет результат A, собирает B и видит, кому стало лучше и какой ценой.

- Две независимые копии допустимых сценариев в памяти браузера.
- Сравнение бюджета, Score, критических показателей и изменений по пяти районам.
- Кнопки восстановить A/B; редактирование текущего плана не меняет сохранённые копии.
- Результаты считать существующим API, формулу на клиенте не дублировать.

Готово, когда можно сравнить пример из ТЗ с собственным сценарием и вернуться к любому из них.
Не требует базы данных и аккаунтов.

## 3. Советник «Улучши мой план»

Пользователь получает конкретную допустимую замену одной меры с объяснением выигрыша и потерь.

- Зафиксировать четыре решения, перебрать допустимые варианты пятого через общий движок.
- Показать предложение и сравнение с текущим планом; применять только отдельной кнопкой пользователя.
- Явно указывать границы поиска: лучшая замена одной меры не равна глобальному оптимуму.
- Без ключа — детерминированный подбор и объяснение; модель может объяснять рассчитанные варианты.
- Настоящий агент с инструментами симулятора — следующий шаг: сделать вызовы и их результаты
  видимыми, не подменять простой поиск надписью «агент».

Готово, когда предложение всегда валидно, числа совпадают с API и применение можно отменить.
Это приоритетное развитие для критерия agentic AI.

## 4. Итоговый отчёт «Мои 5 решений»

Пользователь получает понятный итог своего управления и может показать его жюри.

- Итоговые пять решений, бюджет, Score, районные изменения, риски и компромиссы.
- Чётко отделить рассчитанные факты от текста аналитика, обозначить шаблонный режим.
- Печать страницы или скачивание Markdown без новой PDF-библиотеки.
- Отчёт — снимок конкретного рассчитанного плана; дальнейшее редактирование его не меняет.
- Продумать финальный экран и приглашение сыграть ещё раз; не придумывать рейтинги жителей и проценты.

Готово, когда отчёт читается без пояснений автора, воспроизводит результат и работает без OpenAI.

## 5. Поделиться сценарием

Пользователь отправляет ссылку, другой человек открывает тот же план и проверяет результат.

- Кодировать в URL только идентификаторы решений и районов, без секретов или текста промптов.
- При открытии валидировать и заново рассчитывать план сервером.
- Не доверять Score из URL; для повреждённой ссылки показать понятную ошибку и сброс.
- Кнопка копирования со статусом успеха/ошибки; без регистрации и базы данных.

Готово, когда ссылка на пример воспроизводит 56.54307, а некорректная ссылка не ломает экран.

## Общая готовность каждого модуля

Работает на телефоне от 360 px, имеет загрузку/ошибку/пустое состояние, проходит сценарий без ключа.
Не меняет датасет, правила и контрольные результаты 52.55768 / 56.54307. Изменения идут отдельным PR
с проверками из AGENTS.md и короткой инструкцией в README. Не менять чужие модули без координации.
