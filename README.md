# Аким на 5 часов

AI-симулятор управления городом по кейсу Astana Innovations. [Демо](https://hackalem.oqcrm.kz).

Человек выбирает **ровно 5 разных мероприятий из 14**, назначает районы и укладывается в бюджет 100.
В одном направлении допускается **не более 2 мероприятий**. Система проверяет правила и вычисляет
изменения показателей за 8 кварталов. Аналитик объясняет уже рассчитанный результат.

## Что работает

- Каталог мероприятий, выбор района, бюджет и проверка всех правил.
- Исходные и итоговые показатели пяти районов, Score, критические показатели и синергии.
- Контрольный сценарий из ТЗ одной кнопкой; сброс и повторный расчёт.
- Объяснение результата потоком через OpenAI либо детерминированный отчёт без ключа.
- Автоматические тесты формулы, правил и API без сети.

Это первая рабочая версия. Карта, сравнение сценариев, оптимизатор, агент с инструментами и сохранение
сценариев ещё не реализованы. [Продуктовые задачи для команды](docs/TASKS.md).
[Архитектура](docs/ARCHITECTURE.md) описывает целевое решение, а не готовность всех его модулей.

## Запуск одной командой, без ключа

Нужны `uv`, `pnpm`, Node 20+; Python 3.13 и зависимости устанавливаются через `uv`.
Первый запуск скачивает зависимости; для расчёта и шаблонного аналитика OpenAI не нужен.

```bash
LLM_MOCK=true ./dev.sh
```

Открыть http://127.0.0.1:5173. Бэкенд: http://127.0.0.1:8000, Swagger: `/api/docs`.
Без заданного API-ключа mock включается автоматически. Для настоящего ИИ скопируйте
`backend/.env.example` в `backend/.env`, задайте ключ и запустите `./dev.sh` без `LLM_MOCK=true`.
Ключи не коммитить. Режим аналитика указан в интерфейсе.

## Сценарий проверки и демо

1. Нажмите «Пример из ТЗ»: M7, M8 и M10 в Нуре; M12 для города; M5 в Сарыарке.
2. Проверьте стоимость **95**, остаток **5**, Score **56.54** против исходного **52.56**.
   Без округления: 56.54307 и 52.55768. D_avg = 58.0776, min(D) = 52.9625, N_crit = 0.
3. Выберите Нуру: обеспеченность школами 38 → 48, доступность медицины 35 → 43.75.
   В результате показана синергия M10 + M12.
4. Запросите объяснение. Без ключа оно строится по результату формул; в режиме API текст пишет модель.
5. Удалите одну меру и проверьте план: получите нарушение правила о пяти решениях, без итогового Score.
6. Для проверки несовместимости сбросьте план, выберите M1, M3, M9, M10, M12 и запустите проверку.
   Система сообщит о несовместимости M1 и M3.

Остаток бюджета не добавляет баллов. Не требуется выбирать по одной мере из каждого направления.
Районы и показатели относятся к учебному датасету организаторов, а не к актуальной статистике города.

## Как считается результат

Каждый прямой эффект умножается на `(8 − lag) / 8`. Городские меры действуют на все пять районов.
Синергии применяются отдельно, без уменьшения по лагу. После сложения эффектов значения ограничиваются
диапазоном 0–100. Районный индекс — сумма показателей с весами; D_avg учитывает доли населения.

`Score = 0.7 × D_avg + 0.3 × min(D) − N_crit`

Критическим считается показатель строго ниже 40. Неокруглённые значения используются во всём расчёте;
округление применяется только при отображении. Подробности результата показывают прямые эффекты мер
на показатели, а не аддитивные вклады мер в Score. Расчёт Shapley относится к будущему модулю.

Источник истины: [ТЗ](docs/TZ.md) и [датасет](docs/dataset.json). Runtime-копия
`backend/app/data/dataset.json` входит в релиз; тест проверяет её полное совпадение с исходником.
Значения датасета не изменялись.

## Устройство

- `backend/app/sim.py` — типизированные данные, валидатор, формулы.
- `backend/app/routes/sim.py` — конфигурация, расчёт и объяснение; модель вызывается через `app/llm.py`.
- `frontend/src/pages/SimulatorPage.tsx` — рабочий экран, запросы через `src/lib/api.ts`.
- `GET /api/sim/config` — данные, исходный результат, пример, режим аналитика.
- `POST /api/sim/evaluate` — проверка и расчёт; при нарушениях `result: null`.
- `POST /api/sim/analyze` — SSE-объяснение допустимого сценария.

Тело POST-запросов:

```json
{"decisions":[{"measure_id":"M7","district_id":"nura"},{"measure_id":"M8","district_id":"nura"},{"measure_id":"M10","district_id":"nura"},{"measure_id":"M12","district_id":null},{"measure_id":"M5","district_id":"saryarka"}]}
```

Стек: FastAPI, Python 3.13, Pydantic v2, OpenAI SDK; React 19, TypeScript, Vite, Tailwind CSS v4.
Новых зависимостей для прототипа не добавлено. Правила разработки: [AGENTS.md](AGENTS.md).

## Проверки

```bash
(cd backend && uv run pytest -q && uv run ruff check app tests && uv run ruff format --check app tests)
(cd frontend && pnpm lint && pnpm build)
```

Тесты работают без сети и настоящего ключа. В том числе проверяются все правила, три синергии,
конфликты, порог 40, отрицательные эффекты, ограничение значений, перестановки решений и SSE.
После изменений также пройдите сценарий выше в браузере.

## Деплой

В `main` изменения попадают через PR после зелёных проверок. Выкатывает Орынтай существующим скриптом:

```bash
./deploy/deploy.sh
```

Скрипт проверяет тесты, собирает фронтенд, переключает релиз и проверяет здоровье сервиса; при сбое
возвращает предыдущий релиз. После выкатки нужно пройти контрольный сценарий в демо.
Откат: `./deploy/rollback.sh`. Настройки сервера и `deploy/` для MVP не менялись.
